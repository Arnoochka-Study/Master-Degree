# Сравнение симуляторов по требованиям

|Симулятор|Код открыт|1. Вход — код PyTorch|2. Подключаемые источники времени|3. Гипотезы без расширения|4а. Операторы, зависящие от данных|4б. Коллективные операции|5. Стоимость проверки гипотезы|6. Задание топологии|
|---|---|---|---|---|---|---|---|---|
|Phantora|$\checkmark$|$\sim^{s}$ ч1|$\sim^{s}$ ч3|$\times^{s}$ р1|$\times^{c}$ р2|$\sim^{s}$ ч4|$\checkmark^{s}$|$\checkmark^{s}$|
|NeuSight|$\checkmark$|$\sim^{r}$ ч2|$\times^{c}$|$\times^{c}$|$\times^{c}$|$\times^{c}$ р4|$\checkmark^{r}$|$\times^{c}$ р3|
|ASTRA-SIM 2.0|$\checkmark$|$\sim^s$ ч5|$\sim^s$ ч7|$\sim^c$ ч8|$\times^c$ р5|$\checkmark^s$|$\times^s$ р6|$\sim^s$ ч6|

## Обозначения

|Пишем в markdown|Значение|
|---|---|
|$\checkmark$|выполнено|
|$\sim$ ч1|частично выполнено, пояснение ч1 ниже|
|$\times$|не выполнено|
|$\times$ р1|не выполнено, но можно добавить расширением, способ р1 ниже|
|?|не проверено|

Источник оценки — верхний индекс у отметки: $s$ — по статье, $c$ — по коду, $r$ — проверено запуском. Например: $\checkmark^{c}$, $\sim^{s}$ ч1, $\times^{c}$ р2.

Номер пояснения можно ставить у любой отметки, в том числе у $\checkmark$.

## Пояснения

**Частичное выполнение**

- ч1 — в целом условие выполняется, однако для работы требуется модификация PyTorch.
- ч2 — граф строится трассировщиком. Произвольный PyTorch-код и код с зависящим от данных потоком управления могут не трассироваться. Однако потенциально операторы можно пропатчить.
- ч3 — есть только работа с реальным железом. Но вполне возможно добавить и предсказания.
- ч4 — по сути придётся дописывать ядро.
- ч5 - если верить статье, есть полная поддержка без модификации PyTorch. Но требует прямого прохода на железе
- ч6 - топологии поддерживаются, очень широкий спектр. Но смущает, что они строятся из трех типов (Ring, FullyConnected, Switch).
- ч7 - в целом, есть roofline и замеры из трассы реального прогона, однако нельзя задавать, что как вычислять + roofline не самая точная модель
- ч8 - необходимо создавать новые ET для проверки гипотез. Некоторые можно попытаться синтезировать, но явно не все

**Возможные расширения**

- р1 — реализовано пока только для обучения, но потенциально можно реализовать и для инференса.
- р2 — MoE поддерживается только при равномерной нагрузке: реальные размеры dispatch подменяются равномерными.
- р3 — исходя из простоты симулятора, потенциально можно расширить самому.
- р4 — можно расширять кодом на Python.
- р5 - не совсем понятно, можно ли расширить. С первого приближения - нет. Синтетические трассы MoE из STG тоже предполагают равномерную нагрузку экспертов
- р6 - если гипотеза проверяется на нескольких GPU, то трассу необходимо получать с нескольких GPU, что может создать серьезные проблемы. В теории, можно расширить как-то, чтобы работало на одном GPU, но эмулировало несколько. Также можно попытаться создать синтетическую трассу через STG, но поддерживаются только явно не все модели + пока довольно непонятный способ

## Что полезное есть в симуляторах

- **Phantora** - довольно интересное решение с тем, как можно "обманывать" код torch путем перехватывания коллективных операций из контейнеров
- **NeuSight** - достаточно простое решение как предсказатель, довольно понятно. Плюс преобразование код с помощью fx.graph
- **ASTRA-SIM**. Очень интересные способы моделирования топологий и очень гибкие. Плюс новый способ работы через trace, что может быть очень полезно. Имеет способы работать с Pytorch без модификации кода модели. Потенциально, может использоваться как базис
